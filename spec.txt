Tiny World Language (TWL)

TWL authors dynamic worlds. Everything is an entity; entities are connected by
labeled, multi-valued relations. TWL defines only the triplet grammar and the
entity/relation model. Values are computed with CEL and presented with Mustache,
each used exactly as its published spec defines it.

Conformance invariant

TWL hosts CEL and Mustache; it is not a dialect of either. Every expression is
upstream CEL and every template is upstream Mustache, so the CEL and Mustache
conformance suites must pass unmodified. TWL adds no syntax inside either language
and reinterprets nothing they define -- it only supplies the evaluation context
(host variables, functions, and the entity type). Consequently TWL needs no
parser normalization, desugaring pass, or error interception: the delimiters
(-> for CEL, "..." for Mustache) do all the separation. TWL is its own
serialization, not Turtle, but round-trips losslessly to the RDF/OWL model on
everything that model defines; relation order is a TWL presentation detail that
RDF does not carry, so it is out of scope for the round-trip rather than lost.

Statements

A file is a list of ";"-terminated statements.
Comments: // line, and /* block */.

  Stored fact:    SUBJECT RELATION VALUE;
  Derived fact:   TYPE RELATION -> CEL;

VALUE is one of:
  entity reference   a bare identifier         (Mac, McFlyFam)
  number             123, 1.5
  boolean / null     true, false, null
  string             "..."   (a Mustache template)

Identifiers are Unicode names of letters, digits, and _ - . : with no whitespace,
quotes, brackets, braces, semicolons, or operators. The only reserved words are
instanceof, extends, sameas (and the literals true, false, null).

Entities and relations

Every relation is a total, list-valued field of an entity: self.r is the list of
values of r on self, and is [] when none are asserted -- never an error. A
relation's values are a set: repeated facts are idempotent, so asserting facts in
any order, any number of times, converges to the same graph. Evaluation presents
the values in a deterministic order (insertion order); that order is a TWL
presentation detail and is not part of the RDF round-trip. There are no object
properties; a relation is simply a field whose value is a list.

Ontology (the only built-in relations)

  instanceof  aliases  rdf:type
  extends     aliases  rdfs:subClassOf
  sameas      aliases  owl:sameAs

Inference is the corresponding RDFS/OWL entailment, restricted to these three
relations: if X instanceof A and A extends B then X instanceof B; if A sameas B
then A and B are the same entity. Any other RDFS/OWL vocabulary may be stored as
ordinary facts; TWL does not entail from it (an external reasoner may).

Derived facts

  TYPE RELATION -> CEL;

For every entity bound as self where self instanceof TYPE, the value of RELATION is
the result of the CEL expression. Derived facts are lazy, evaluated on read.
Precedence, highest first: a stored fact overrides a derived one for the same
subject and relation; a more specific TYPE (by extends) overrides a less specific
one. Use Entity as the global fallback type. (See the precedence note in the
example.)

Computation: CEL, unchanged

The text after -> is Common Expression Language, used verbatim
(https://github.com/google/cel-spec; pin a version -- its conformance suite is
normative). CEL is non-Turing-complete, side-effect-free, and guaranteed to
terminate, so TWL has no loops, recursion, or functions of its own. TWL supplies
only the evaluation context -- CEL's standard host mechanism, which adds no syntax:

  self                the current entity
  now                 a timestamp, frozen per evaluation (now.getFullYear() etc.)
  instances(Type)     the list of entities that are instanceof Type
  e.r                 field access: the list of values of relation r on entity e

Because TWL adds no syntax, every operation is plain CEL:
  traverse:  self.family.map(f, f.name)
  select:    instances(Person).filter(p, McFlyFam in p.family)
  scalar:    self.bornYear[0]

TWL deliberately has no dot-flatten or bracket-selector sugar. Field selection on
a list is an error in CEL -- asserted by the conformance test
list_field_select_unsupported -- and a Type[...] selector would collide with CEL's
own [] indexing. Either would force TWL to reinterpret CEL syntax, which the
conformance invariant forbids. Use .map and .filter.

Presentation: Mustache, unchanged

A string value is a Mustache template (https://github.com/mustache/spec; its YAML
conformance suite is normative), rendered against an entity as context. Templates
present only; anything dynamic is first defined as a CEL derived relation and
referenced here by relation name.

  {{ r }}            interpolate relation r of the current entity
  {{# r }}..{{/}}    iterate relation r, binding each value as the current entity

A relation is a list, so {{# r }} is Mustache's standard list section. For the one
case Mustache leaves undefined -- interpolating a list with {{ r }} -- TWL renders
its values in order (so a single-valued relation renders as its value, an empty
one as "").

Budget (the only safety mechanism TWL enforces)

CEL and Mustache already terminate, so abuse can only come from the TWL layer:
relation traversal, derived-relation chains, and template expansion. Evaluation
runs under a fixed budget -- max traversal depth, max derived-relation recursion
depth with cycle detection, max result-list length, max total output size.
Exceeding the budget is an error.

Example

  Entity name "Entity";
  Person extends Entity;
  Family extends Entity;

  Person age      -> now.getFullYear() - self.bornYear[0];
  Person lastName -> self.family.map(f, f.name);
  Person enemies  -> instances(Person).filter(p,
                       McFlyFam in p.family && !("Lorraine" in p.firstName));

  McFlyFam instanceof Family;
  McFlyFam name "McFly";

  Marty instanceof Person;
  Marty firstName "Marty";
  Marty bornYear 1968;
  Marty family McFlyFam;

  Lorraine instanceof Person;
  Lorraine firstName "Lorraine";
  Lorraine family McFlyFam;

  Biff instanceof Person;
  Biff persona "A bully with disdain for:
  {{# enemies }}- {{ firstName }} {{ lastName }}
  {{/}}";

  // Precedence: stored beats derived, and a more specific type beats a general one.
  //   Marty age 17;                              // Marty.age is 17, not the derived value
  //   Entity title -> "-";  Person title -> "Citizen";   // a Person gets "Citizen"
