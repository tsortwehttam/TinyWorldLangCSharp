Tiny World Language (TWL)

TWL authors dynamic worlds. Everything is an entity; entities are connected by
labeled, multi-valued relations. TWL itself defines only the triplet grammar and
the entity/relation model. Every value sublanguage is a referenced standard, so
the language is small and its behavior is pinned to specs with conformance suites
rather than to prose that can be reinterpreted. See Footnotes for the standards.

Statements

A file is a list of ";"-terminated statements.
Comments: // line, and /* block */.

  Stored fact:    SUBJECT RELATION VALUE;
  Derived fact:   TYPE RELATION -> CEL;

VALUE is one of:
  entity reference   a bare identifier              (Mac, McFlyFam)
  number             123, 1.5
  boolean / null     true, false, null
  string             "..."   (may embed templates — Footnote T)
  selector           Type[ ... ]                    (Footnote S)

Identifiers are Unicode names of letters, digits, and _ - . : with no whitespace,
quotes, brackets, braces, semicolons, or operators. The only reserved words are
instanceof, extends, sameas (and the literals true, false, null).

Entities and relations

Every relation is multi-valued. Repeated facts append. A missing relation is [].
Relation access self.r returns the list of values of r on self. Access continued
over a list maps and flattens: list.r == list.flatMap(x, x.r). (Footnote D)
There are no object properties; dot access is relation traversal.

Ontology (the only built-in relations)

  instanceof  aliases  rdf:type
  extends     aliases  rdfs:subClassOf
  sameas      aliases  owl:sameAs

Inference is the corresponding RDFS/OWL entailment, restricted to these three
relations: if X instanceof A and A extends B then X instanceof B; if A sameas B
then A and B are the same entity. (Footnote O)

Derived facts

  TYPE RELATION -> CEL;

For every entity bound as self where self instanceof TYPE, the value of RELATION is
the result of the CEL expression. Derived facts are lazy, evaluated on read. A
stored fact for the same subject and relation overrides the derived one. A more
specific TYPE (by extends) overrides a less specific one. Use Entity as the global
fallback type.

Expressions are CEL

Every expression -- after ->, inside selector filters, and inside {{ }} in
templates -- is Common Expression Language. CEL is non-Turing-complete,
side-effect-free, and guaranteed to terminate, which is why TWL has no loops,
recursion, or user-defined functions of its own. The operators, types, functions,
and the comprehension macros filter/map/exists/all are CEL's; unknown names are
errors. (Footnote C)

TWL supplies three host bindings to CEL -- this is CEL's normal extension
mechanism, not a change to the language:
  self                the current entity
  now                 a timestamp, frozen per evaluation (use now.getFullYear() etc.)
  instances(Type)     the list of entities that are instanceof Type

Footnotes

C  CEL: https://github.com/google/cel-spec -- pin a version; its conformance test
   suite is the normative semantics. TWL uses CEL unchanged except for Footnote D.

D  Member access continued over a list maps and flattens, and a missing relation
   yields []: self.r.s == self.r.flatMap(x, x.s). This is the one TWL extension to
   CEL member access. (Pure-CEL alternative, no extension: write self.r.map(x, x.s).)

O  instanceof / extends / sameas alias rdf:type / rdfs:subClassOf / owl:sameAs;
   inference is the matching RDFS/OWL entailment over just those three relations.

S  Selector sugar. Type[P1][P2] desugars to the CEL set
     instances(Type).filter(self, P1 && P2)
   Inside a filter Pi a bare relation name r means self.r; r = v means v in self.r;
   and r OP v (OP one of < <= > >= !=) means self.r.exists(x, x OP v). A comma
   between selectors is set union.

T  Templates. A string may contain Mustache (https://github.com/mustache/spec; its
   YAML conformance suite is normative). {{ EXPR }} interpolates a CEL expression.
   {{# SELECTOR }} ... {{/}} iterates the selector, binding each entity as self in
   the body. (The bracketed section key is the one TWL extension to Mustache.)

Budget (the only safety mechanism TWL must enforce)

CEL and Mustache already terminate, so abuse can only come from the TWL layer:
relation traversal, derived-relation chains, and template expansion. Evaluation
runs under a fixed budget -- max traversal depth, max derived-relation recursion
depth with cycle detection, max result-list length, max total output size.
Exceeding the budget is an error.

Example

  Entity name "Entity";
  Person extends Entity;
  Family extends Entity;

  Person age      -> now.getFullYear() - self.bornYear;
  Person lastName -> self.family.name;

  McFlyFam instanceof Family;
  McFlyFam name "McFly";

  Marty instanceof Person;
  Marty firstName "Marty";
  Marty bornYear 1968;
  Marty family McFlyFam;

  Lorraine instanceof Person;
  Lorraine firstName "Lorraine";
  Lorraine family McFlyFam;

  Biff persona "A bully with disdain for:
  {{# Person[family=McFlyFam][firstName!=\"Lorraine\"] }}
  - {{ self.firstName }} {{ self.lastName }}
  {{/}}";
