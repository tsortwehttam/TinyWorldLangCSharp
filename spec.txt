Tiny World Language (TWL)

TWL is a small language for authoring dynamic worlds. In TWL, everything is an entity. Entities are connected by labeled, multi-valued relations. This, TWL simply defines a triplet grammar and and entity/relation model.

Values are computed with CEL and presented with Mustache. Evaluation runs under a fixed budget (max traversal depth, max derived-relation recursion depth with cycle detection, max result-list length, max total output size). Exceeding the budget is an error.

Conformance invariant

TWL hosts CEL and Mustache. Every expression is upstream CEL and every template is upstream Mustache, so the CEL and Mustache conformance suites must pass unmodified. TWL only supplies the evaluation context to these systems (host variables, functions, and the entity type).

TWL isfaithful subset of the RDF/OWL model: every TWL fact graph is an RDF graph (lossless out), while TWL omits by design what it does not need (rich datatypes, arbitrary IRIs, blank nodes).

Statements

A file is a list of ";"-terminated statements.

Comments:       // line, and /* block */.
Stored fact:    SUBJECT RELATION VALUE;
Derived fact:   TYPE RELATION -> CEL;

VALUE is one of:
  entity reference   a bare identifier         (Mac, McFlyFam)
  number             123, 1.5
  boolean / null     true, false, null
  string             "..."   (a Mustache template)

Identifiers are Unicode names of letters, digits, and _ - . : with no whitespace, quotes, brackets, braces, semicolons, or operators.

The only reserved words are:
  instanceof
  extends
  sameas
  true
  false
  null

Entities and relations

Every relation is a total, list-valued field of an entity: self.r is the list of values of r on self, and is [] when none are asserted (never an error). A relation's values are an unordered set: repeated facts are idempotent, so asserting facts in any order, any number of times, converges to the same graph.

Where evaluation needs a sequence (indexing, rendering), it uses a canonical order derived from the data -- entity values by id, literals by value -- so the order is deterministic and survives merge and the RDF round-trip.

The set carries no authoring order. When order is part of the world, model it as a fact and sort on it explicitly (sortBy, below). There are no object properties; a relation is simply a field whose value is a list.

The only built-in ontology relations are:
  instanceof  (aliases rdf:type)
  extends     (aliases rdfs:subClassOf)
  sameas      (aliases owl:sameAs)

Inference is the corresponding RDFS/OWL entailment, restricted to these three relations: if X instanceof A and A extends B then X instanceof B; if A sameas B then A and B are the same entity. Any other RDFS/OWL vocabulary may be stored as ordinary facts; TWL does not entail from it (though an external reasoner may).

Derived facts

  TYPE RELATION -> CEL;

For every entity bound as self where self instanceof TYPE, the value of RELATION is the result of the CEL expression. Derived facts are lazy, evaluated on read.

Precedence, highest first: a stored fact overrides a derived one for the same subject and relation; a more specific TYPE (by extends) overrides a less specific one. Use Entity as the global fallback type. (See the precedence note in the example.)

Computation: CEL

The text after -> is Common Expression Language, used verbatim (https://github.com/google/cel-spec).

CEL is non-Turing-complete, side-effect-free, and guaranteed to terminate, so TWL has no loops, recursion, or functions of its own. TWL supplies only the evaluation context -- CEL's standard host mechanism, which adds no syntax:

  self              the current entity
  now               a timestamp, frozen per evaluation (now.getFullYear() etc.)
  instances(Type)   the list of entities that are instanceof Type
  sortBy(list, key) list ordered by the relation named key (a string)
  e.r               field access: the list of values of relation r on entity e

Because TWL adds no syntax, every operation is plain CEL:
  traverse: self.family.map(f, f.name)
  select:   instances(Person).filter(p, McFlyFam in p.family)
  order:    self.children.sortBy("bornYear")
  scalar:   self.bornYear[0]

Presentation: Mustache

A string value is a Mustache template (https://github.com/mustache/spec; its YAML conformance suite is normative), rendered against an entity as context. Templates present only; anything dynamic is first defined as a CEL derived relation and referenced here by relation name.

  {{ r }}         interpolate relation r of the current entity
  {{# r }}..{{/}} iterate relation r, binding each value as the current entity

A relation is a list, so {{# r }} is Mustache's standard list section. For the one case Mustache leaves undefined -- interpolating a list with {{ r }} -- TWL renders its values in order (so a single-valued relation renders as its value, an empty one as "").

Example

  Entity name "Entity";
  Person extends Entity;
  Family extends Entity;

  Person age -> now.getFullYear() - self.bornYear[0];
  Person lastName -> self.family.map(f, f.name);
  Person enemies -> instances(Person).filter(p, McFlyFam in p.family && !("Lorraine" in p.firstName));

  McFlyFam instanceof Family;
  McFlyFam name "McFly";

  Marty instanceof Person;
  Marty firstName "Marty";
  Marty bornYear 1968;
  Marty family McFlyFam;

  Lorraine instanceof Person;
  Lorraine firstName "Lorraine";
  Lorraine family McFlyFam;

  Biff instanceof Person;
  Biff persona "A bully with disdain for:
  {{# enemies }}
    - {{ firstName }} {{ lastName }}
  {{/}}";
